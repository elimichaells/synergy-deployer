Administrators can rename PostgreSQL databases from Storage → database → Settings → Review rename, or Storage → Servers → Rename. The review lists linked apps and matching settings found in .env, .env.local, .env.production and .env.production.local, including custom database URLs. Applications outside Manager and externally stored secrets need a separate review.

Stop all applications and workers using the database and close database clients first. Manager blocks protected databases, name conflicts, active sessions and current data operations. The administrator must type the current name and acknowledge updating all application connections.

Renaming preserves data and credentials. Manager updates every matching Storage link (including localhost aliases) and applicable backup schedules. It does not edit application files, stop processes or restart them. Update saved environment files, database URLs, custom database variables, CI secrets and external clients with the new name, then restart or redeploy all affected apps. Managed connection variables use the updated Storage link on the next deployment; adopted connections and custom settings remain the user's responsibility.

Rename reminders and affected app links remain visible in Storage after reload. Rename history and an audit entry record the change. A failure before committing rolls back database and metadata transactions. If the remote database commit or the Manager commit cannot be verified, history is marked needs_review and further renames are blocked until an administrator reconciles the database name and Manager links. Database contents are never copied or deleted by this operation.
