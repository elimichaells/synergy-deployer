# Manager 2.16.0 — health history and reliable releases

Released 19 October 2026.

## Health and alerts

- Readiness alerts identify the affected service, failing dependency, endpoint, expected and observed response, response time, first occurrence and last confirmation. Each alert links to its application when available and provides a specific next step.
- Failed JSON health responses are classified into fixed, safe descriptions. Raw response bodies, credentials, stack traces and connection URLs are never stored in monitoring history.
- Health history offers service filtering and 1-hour, 24-hour and 7-day views, with readiness and response-time charts plus a tabular summary. Observations are collected once per minute, rolled up into five-minute buckets and retained for seven days. Seven-day charts aggregate hourly.
- The independent monitor persists history beside its state file, using atomic writes and an exclusive writer lock. On first use, it imports the existing hour of observations. It does not invent older data.
- Missing observations, unknown checks, partial coverage and intentionally paused services remain distinct from successful checks. Percentages describe completed readiness samples, not every user request or a contractual uptime measure.

## Included reliability fixes

This release records the previously deployed improvements: configurable application readiness, independent monitoring and unified alerts, guarded PM2 startup, incremental deployment logs, bounded and redacted runtime diagnostics, Git ownership error guidance, deployment disk guards, managed backup credentials and database rename safeguards.

Existing manual preflight and HTTP health-check options remain explicit. Disabling HTTP checks does not establish readiness; final release records state when readiness was not verified. Application database issues remain alerts until their checks actually recover.

The release also updates Next.js within the 15.5 patch line and refreshes the SQL Server driver, image-processing and source-map dependencies. The Tailwind animation plugin is a development dependency used only to compile CSS. Production deployment uses a clean runtime-only install after the build. Development tooling still requires its own audit; production audit success does not mean that every development dependency is free of advisories.

## Release verification

The package version, lockfile versions and Git tag must agree. Official packages require a clean source checkout and include source-commit metadata and a SHA-256 receipt. The release workflow runs locked dependency installation, tests, a production dependency audit and a production build before creating installer assets. The Health & alerts page displays the version and build's source commit. Local deployment logs are excluded from release source and packages.

`MANAGER_PREVIEW=1` disables startup schedulers, job recovery, schema initialization and Caddy rewrites for isolated build and preview processes. Middleware rejects write requests and app wake requests in preview mode. It must not be set on the active production Manager. Preview access must be restricted to loopback.

## Production rollout and rollback

Build and test in an independent source checkout with a separate dependency tree. Preserve the live source fingerprint, private configuration, monitor state, process inventory and previous compiled build before activation. Stop only Manager after confirming no deployment, backup, migration, runtime installation or cron job is active. Do not run the installer on an existing production server to apply this update.

The rollback package must retain the previous compiled build, source and dependency tree. Restore those together if verification fails. Monitor state remains version 1; the separate `history.json` is additive and can be retained when rolling back. Never overwrite recent monitoring observations with an old snapshot.

No application database migrations, role changes, global PM2 restarts or automatic restarts are introduced by this release. Alerts remain inside Manager.
