# Manager 2.30.4

Health & alerts and AI Operations now offer the same cross-page shortcuts on host and remote servers. Both shortcuts retain the selected server instead of returning to the manager host.

SSH setup now allows up to 90 seconds for the first verified monitoring sample, covering cold Windows service and memory-counter initialization. The SSH lab exercises the bundled agent, dedicated service identity, service restart, updates and automatic rollback.

Database memory totals and tuning status remain unknown until inspection provides measurements and a verified service. A detected client without saved connection credentials no longer appears to use zero memory or to have verified settings.

Remote infrastructure now uses the host's shared navigation and page components for Memory, Disk cleanup, Jobs & workers and AI Operations. These pages use server-scoped APIs and the selected agent; they never fall back to host commands.

- Memory includes process-tree accounting, history and warnings, app memory limits, reviewed direct starts with readiness rollback, and staging idle sleep with a loopback wake gateway.
- Cleanup previews and removes expired Manager-owned deployment workspaces. Current releases, recent successes, pinned folders, process and schedule references, unknown files, links and recovery records are protected. Daily cleanup is opt-in per remote server.
- Scheduled jobs run through the selected agent. Background workers have isolated private process identities, controls and logs; existing server processes are not adopted.
- Operations uses scoped settings, anonymous AI evidence, uptime history, database configuration review and expiring app-specific restart reviews. Healthy, stale or changed applications cannot be restarted through recovery.
- Database inspection uses existing saved loopback connections. Windows MySQL and MariaDB tuning requires a verified service and fresh recommendations, validates configuration and restores the previous file when the service fails to restart. PostgreSQL and unverified services remain inspection-only, as on the host.
- Connected and unfinished servers can be renamed. Names are validated, concurrent edits are detected, and directory labels refresh without changing connection details.
- Server removal also explains the effect on schedules and workers and removes the new scoped management records.

The installer includes agent 1.7.0 and its resource module in a single downloadable/updateable bundle. Existing servers need the agent update from Agent access & updates before using the new resource controls. Legacy agents remain supported for their existing features. Production applications are never placed behind the staging wake gateway.

Validation covers shared navigation, server isolation, authorization, job admission, cleanup boundaries, restart rollback, gateway routing, database migrations and installer packaging. A completely fresh Windows VM installation and reboot remains a separate acceptance test; the production servers used for verification retain their existing applications.
