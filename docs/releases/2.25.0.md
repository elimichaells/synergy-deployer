# Manager 2.25.0

Workspace tabs are smaller and show server, application and environment context.
Connected servers now have an overview, application pages, deployment history and
server access sections that follow the Manager host's navigation. Stale monitoring
data remains clearly identified, and navigation protects unsaved settings.

New applications on connected Windows and Linux servers use the same six guided
steps: Source, Build, Database, Environment, Domain and Deploy. Repository
inspection detects Next.js, Angular, Node.js, Go and Laravel without executing
repository scripts. Build commands remain editable and use platform-specific
defaults where needed.

Choose production only, staging only, or both. Each environment has its own branch,
port, hostname, encrypted variables, database connection and saved setup progress.
Staging-only creation does not create a production application. The database step
can create a PostgreSQL, MySQL or MariaDB database and app account, attach an
existing connection, or explicitly choose no database. Final server checks verify
prerequisites, ports and the database connection before allowing deployment.

LAN and WAN addresses use the existing Caddy configuration. Internal DNS and client
trust for the institution's certificate authority remain administrator-managed.

## Requirements and update

Guided setup requires remote agent 1.1.0. New SSH enrollments install this version.
For an existing server, download the current agent from Server access, stop only
its agent service while no job is running, replace the script and restart that
service. Preserve its enrollment and data folder. Updating Manager does not
automatically replace remote agents.

Required runtimes, package managers, database engines and database client tools
must already be installed for the agent account. Database creation can partially
finish after interruption; saved credentials support testing a repaired connection.
Application rollback does not reverse database migrations or other data changes.

Managers on 2.21.0 or newer can install the signed release through Settings > Manager
updates, or import the matching Node.js 22/24 package offline. The updater retains
the previous release and database/configuration backups. Hosted applications keep
running during the Manager update.

## Validation

Local checks covered the production build, types, lint, the full test suite and a
22-test focused run with real PostgreSQL provisioning and credential verification.
Browser preview checks covered both platforms, separate environments, saved setup
progress, unsaved changes and narrow layouts. MySQL/MariaDB command handling was
tested with isolated fixtures; real remote-host deployment tests remain separate.
GitHub runs Windows/Linux compatibility checks and release validation before
publishing signed packages.
