# Manager 2.27.1

This release includes the shared host/remote management workflows and hardens
the Windows installer used for new Manager installations.

## Fresh Windows installation

- Protect existing Caddy site configuration, Manager startup configuration,
  encryption keys, database names and PostgreSQL roles. A fresh installation
  never silently adopts an old control database or resets an existing role's
  password.
- Detect conflicts between Manager, database, Caddy and database-client ports
  before provisioning. Detect existing PostgreSQL services, including stopped
  services, before creating a new control server.
- Distinguish PostgreSQL client tools from complete server binaries and a
  running database. Reuse complete tools, initialize a missing selected control
  cluster, and refuse to install an unselected control server. Custom tool paths
  are supported through `PostgreSqlBinDirectory` or
  `MANAGER_INSTALL_POSTGRESQLBINDIRECTORY`.
- Preserve non-ASCII PostgreSQL administrator passwords through protected UTF-8
  connection files, and restrict access to temporary database setup scripts.
- Verify the expected Manager release, database readiness, new administrator
  login, administrator session and server-management API before reporting
  successful installation.

Download the `manager-setup-2.27.1-*.exe` graphical installer, or the
`manager-windows-2.27.1-*.zip` command-line package. Each has a matching
`.sha256.json` checksum manifest. The EXE embeds the Manager source package;
installing dependencies still requires internet access. It is not the full
offline-dependency edition.

## Connected server management

Host and remote workspaces share project, application, resource and runtime
components. Remote **Infrastructure > Runtimes** supports installed-version
inventory, additional installations and application runtime selection. Remote
service setup detects existing services and accepts custom paths, while managed
installations use isolated locations and preserve existing sites.

Remote applications include console commands, logs and cancellation. Agent
1.5.0 includes service installation and runtime version management. Existing
agents must be upgraded from **Infrastructure > Agent access & updates**;
updating Manager alone does not automatically upgrade them. Service and runtime
availability still depends on the selected server's operating system.

## Updates and validation

Existing Managers can use **Settings > Manager updates** or import the matching
Node.js 22/24 update package. The update keeps the previous release and
database/configuration backups. Migration 028 adds remote-operation tracking.

Installer regression checks cover conflicts, service reuse, protected paths,
readiness and login failures. A separate local integration test created two
isolated PostgreSQL clusters, initialized the administrator and application
database provider, and verified that existing database data and role passwords
were preserved when duplicate names were rejected.

A complete fresh Windows installation and reboot have not been verified for
this release. After installation, verify client HTTPS access, certificate trust,
administrator sign-in and automatic startup after reboot using the
[installer guide](../../installer/ManagerSetup/README.md).
