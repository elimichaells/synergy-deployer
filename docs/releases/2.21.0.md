# Manager 2.21.0

Manage Windows and Linux servers through guided SSH enrollment, monitor them,
and deploy multiple applications per server. Caddy supports institution LAN
hostnames and WAN domains; LAN clients need the institution's DNS and CA trust.

## Updates and recovery

Settings → Manager updates adds verified online and offline updates, retained
previous releases, database/configuration backups, health checks, automatic
rollback and recovery independent of the Manager process. Update packages have
GitHub/Sigstore build signatures verified offline. These signatures are not
Windows Authenticode signatures for the installer executable.

Updates briefly restart Manager and its dashboard helpers. Hosted applications,
Caddy, database engines and the PM2 daemon remain running. Database snapshots
are retained for manual recovery; rollback preserves subsequent user data and
compatible additive schema changes.

## Existing Managers: one-time upgrade

For Windows x64 Manager 2.17–2.20 with the standard SYSTEM PM2 startup task and
Node 22 or 24, download `bootstrap-manager-upgrade.ps1` from this release and run
in **Administrator PowerShell**:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\bootstrap-manager-upgrade.ps1 -ManagerRoot C:\web\manager
```

It downloads the matching prebuilt package, verifies the publisher, stages,
registers recovery, backs up and upgrades automatically. Run while no other
administrator is deploying or changing databases. No npm install or build runs
over the existing installation. Afterward, future releases install from Settings.

For **offline institutions**, copy these assets together:

- `bootstrap-manager-upgrade.ps1`
- `manager-bootstrap-runtime.zip`
- `manager-update-win32-x64-node22.tar` or `manager-update-win32-x64-node24.tar`

Then run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\updates\bootstrap-manager-upgrade.ps1 -ManagerRoot C:\web\manager -OfflineDirectory D:\updates
```

For custom LAN/WAN URLs add `-ManagerUrl https://manager.example.edu`. For an
internal Caddy CA also add `-CaCertificate C:\certificates\caddy-root.crt`.
Obtain the initial script from this official release over HTTPS: it pins the
bootstrap ZIP hash and supplies the first trust anchor for older installations.

## Deployment fix

Fixes Windows isolated deployments failing with **“Expected a Git command”**.
Workspace permission setup now uses a separate system-command runner instead
of the Git-only runner. The informational message about files rewritten by a
previous install/build is unrelated. Failed preparation retains the old app.

See [update and recovery documentation](https://github.com/elimichaells/synergy-deployer/blob/v2.21.0/docs/manager-updates.md)
and [remote server setup](https://github.com/elimichaells/synergy-deployer/blob/v2.21.0/docs/remote-servers.md).
