# Manager 2.34.1

This release supersedes the unreleased 2.34.0 installer build. Signed pushes arriving during a deployment are queued durably and run sequentially. Duplicate deliveries reuse the same job; setup, console and storage operation locks remain enforced.

Waiting pushes appear in deployment history and can be cancelled. Revoking server
access cancels them and erases their queued credentials. The existing unique
active-job constraint is retained; an additive encrypted waiting queue advances
in the same transaction that finishes or cancels the preceding deployment.
If the preceding release already includes the pushed commit, the duplicate is
recorded as skipped without restarting the application again.

Connected-server applications and project app lists now expose the same quick
auto-deploy control as the Manager host. Enabling it connects a verified GitHub,
GitLab or Gitea push webhook before saving the enabled state. Failed provider
configuration leaves auto-deploy disabled. Disabling remains available when Git
credentials expire. Incomplete setup and disconnected servers cannot enable it.

Changing a remote application's repository or Git connection clears its previous
webhook authorization. Re-enable auto-deploy after reviewing the new source;
guided apps must complete inspection and server checks first. Guided application
settings now include the app name and source editor, plus an Open setup shortcut.

Remote staging pages expose the existing shared promotion review. Host and remote
build settings expose pre- and post-deploy commands. Remote application overviews
include the shared tool grid, with jobs and other links kept on the selected server.
Project Storage uses the full database catalog and shared Add service dialog;
creation waits for the agent's receipt before sharing the resulting database.
Application and project summaries also use the full catalog, including additional
and shared databases, instead of showing only the original setup database.

No agent update or production application redeployment is required for these
controls. Agent 1.9.2 remains current. This release does not change existing service
installations, database contents, Caddy routes or auto-deploy preferences by itself.

Validation includes the regression suite, production build, three-provider webhook
tests and isolated PostgreSQL tests for encrypted webhook persistence, exact pushed
commits, duplicate deliveries, source changes, setup command persistence and storage
receipts. Provider calls use fixtures; no existing production repository's webhook
was changed for testing.

Full parity is not yet established. Remote deployment always checks readiness after
activation but does not expose the host's optional candidate preflight switches.
Provider comparison history, complete cross-provider migration checksums and a real
fresh-install operating-system reboot remain outside this release's verified scope.
See [the module audit](../server-feature-parity.md) for other evidence boundaries.
