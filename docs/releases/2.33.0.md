# Manager 2.33.0

Connected servers can now apply reviewed service upgrades from **Runtimes & tools**.
An administrator selects the existing installation and approves a plan; Manager
downloads, verifies and applies the selected release, then checks readiness.
Existing sites and service settings are preserved. Updates are not unattended.

- Private phpMyAdmin updates replace the complete client release while retaining
  configuration, sessions, secrets and PHP settings. Remote clients are checked
  under the agent account; the Manager host checks its private helper's login page.
- Supported native database updates stay on the installed release series, require
  paused writers and an existing administrator login, and make a verified cold
  backup before replacing binaries. The authenticated database must match the
  selected service process and data directory.
- Caddy supports a direct native service or the agent's private PM2 process.
  Custom module requirements and the existing configuration are checked before
  activation. PM2 upgrades operate only on the agent's private daemon and preserve
  application definitions and stopped states.
- Composer, Sling, sqlcmd, Angular CLI and portable Windows Git have verified
  update paths. sqlcmd maintenance leaves the SQL Server engine running. Composer
  and MySQL version detection now ignore unrelated PHP versions and old folder names.
- Failed or interrupted operations retain recovery files. Database restoration
  requires an explicit review and retains post-upgrade data separately. Conflicting
  deployments, database operations and Manager/agent updates stay blocked until
  the operation is resolved.

Validation uses disposable Windows and Ubuntu service installations, private
PM2/Caddy fixtures and private database/browser tests. It covers upgrades, real
authenticated reads, cold-backup restoration and preservation of unrelated files
and processes. Production applications are not service-upgrade test fixtures.

The [service upgrade guide](../service-upgrades.md) lists platform and installation
requirements. Linux package-owned PostgreSQL/MySQL/MariaDB/Git/PHP/Python, Windows
Python, licensed Windows Redis and SQL Server engine upgrades still use vendor
maintenance. Replication, clusters, major database migrations and unsupported
service wrappers require their own maintenance procedure. OS reboot verification
remains outstanding; this release does not claim universal functional parity.

Agent 1.9.1 remains the required/current agent. This release includes the SSH
maintenance helpers in Manager; it does not change the agent protocol.
