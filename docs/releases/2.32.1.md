# Manager 2.32.1

This is the first published installer for the 2.32 changes. Release validation now installs locked dependencies in both source checkouts so offline agent packaging is tested against actual package files. The 2.32.0 packaging attempt stopped before publication.

Connected servers now use more of the same application and infrastructure controls
as the Manager host. Agent 1.9.0 is required for the new remote operations; update
connected servers from **Agent access & updates** after updating Manager.

- Application removal uses the same reviewed confirmation flow. Removing an
  application detaches its management record and archives that record encrypted.
  Running processes, files, databases, DNS and proxy routes remain intact. Remote
  applications require an authenticated preservation receipt; conflicting active
  jobs, workers and shared paths are reported before removal.
- Application pages share console controls and completion, environment-file
  editing, deployment scripts, security settings, promotion, workers and history.
  Switching servers clears forms and pending reads from the previous scope.
  Console Git commands can use the saved repository connection without exposing
  its credential to ordinary shell commands.
- Database workspaces share browsing, SQL, backup, provisioning, connection
  settings, migration reviews and recovery. MongoDB authentication databases and
  custom TLS options survive connection registration and application attachment.
  PostgreSQL database moves and account switches include application readiness,
  rollback and interrupted-operation reconciliation.
- Connected Windows and Linux servers can install an optional private phpMyAdmin
  client through Runtimes & tools. It is reached through the existing agent,
  without adding a web listener or changing existing proxy sites. Admin-created
  sessions last 30 minutes, use a database login and limit transfers to 8 MB.
  Browser preferences and query history are temporary. The Windows client uses
  PHP 8.3.36, including its security fixes and explicit private CGI configuration.
- Tool update checks use official release catalogs, retain results across refresh
  and show unavailable checks individually. Database checks stay on the installed
  release series. Node.js, Go and Windows PHP support separate project versions.
- Remote MongoDB, Windows SQL Server Express, Linux Redis and Sling installation
  are verified against existing-service, port and data protections. Database
  installation and reuse preserve pre-existing services and application data.
  Release cleanup protects current, detached and referenced application paths.

## Validation and limits

The audit combines shared-page browser comparisons with isolated PostgreSQL,
MySQL/MariaDB, MongoDB, SQL Server, Redis, Caddy and PM2 tests. Windows and Linux
PM2 6/7 labs exercise deployment, rollback, workers, Git promotion, console access,
cleanup and removal receipts. Separate service-installation labs run on disposable
Windows and Ubuntu runners. No production application was removed for validation.

This release does not claim that every platform supports identical operations:

- Existing non-versioned services still require a vendor maintenance update and
  subsequent verification through Reuse installation. Automatic replacement of
  the private phpMyAdmin client is not yet available.
- Windows Redis requires an existing production-licensed installation or external
  connection. Linux SQL Server uses an existing installation.
- Removal preserves resources; it is not an application uninstall or database
  deletion. The encrypted removal archive does not yet have a recovery UI.
- Cross-provider migrations do not provide full content checksums. PostgreSQL
  database moves do validate contents and sequence values.
- OS reboot verification remains outstanding: earlier disposable VMs did not
  return a post-boot report, and no spare server was available. Service restart
  tests do not establish reboot recovery.

See the [page and module audit](../server-feature-parity.md) for evidence and
remaining verification boundaries.
