# Manager 2.31.0

Applications can now use a private server IP and HTTPS port directly, without
Cloudflare, public DNS or a purchased domain. **Institution LAN / private IP** is
available in the shared Domains & DNS workspace and connected-server application
setup. IPv4 private ranges and IPv6 unique local addresses are supported.

- The same address fields, URL preview and certificate instructions appear for
  the Manager host and connected servers. Each server provides its own public CA
  certificate for institution devices to trust.
- Addresses must belong to the selected server. Occupied HTTPS ports are rejected
  before proxy configuration changes; failed reloads restore the prior file.
  Existing application routes remain present.
- Separate institutions can reuse private IP ranges. Each application on the same
  IP uses its own available HTTPS port. Project links and staging wake requests
  preserve the port and IPv6 address.
- Caddy administration requests include the required Origin header. The host CA
  download prefers the active proxy's certificate, including custom storage paths.
- Agent 1.8.0 advertises IP-only deployment support. Existing servers need this
  update before accepting the new operations.

Fresh Windows setup now copies the actual Caddy executable from Chocolatey rather
than its non-portable launcher and verifies it before building Manager. Database
inspection recognizes MariaDB service arguments that quote the entire custom
configuration option and allows more time for cold Windows inspection. MySQL and
MariaDB tuning confirms that the selected service owns the restarted listener.
Automatic update registration, health monitoring and reviewed recovery support
both PM2 6 and PM2 7. Connected Windows servers collect memory through native
counters without waiting for WMI initialization. Log redaction preserves complete
secrets when longer and shorter values overlap across output chunks.

Isolated Windows acceptance labs exercise private-IP HTTPS, preservation of an
existing site, conflicting ports, public certificate download, real MySQL/MariaDB
tuning and rollback, and fresh installation with independent post-reboot checks.
Windows/Linux agent and PostgreSQL integration tests cover server isolation and
overlapping institution address ranges.

Institutions must permit the selected HTTPS ports from their client networks and
distribute each server's public CA certificate. SSH onboarding needs network access
to the target server; manual enrollment or a VPN supports separate private LANs.
Repository access and dependency installation still need their configured sources
or local mirrors. See [LAN deployment instructions](../lan-deployments.md).
