# Manager 2.23.0

Infrastructure now includes **Disk cleanup** with disk capacity, a read-only
release scan, manual cleanup, per-folder decisions and recent activity.
Administrators can enable daily automatic cleanup independently on each Manager.
Automatic cleanup starts disabled when upgrading.

Cleanup keeps the current deployment and the latest three successful deployment
workspaces. Other successful workspaces stay for at least seven days; failed or
cancelled builds stay for three days. The newest dependency snapshot is retained;
older caches expire after seven days. A `.keep` entry pins a folder indefinitely.

Only recognized, terminal deployment workspaces and regenerable dependency caches
inside each application's `.manager-releases` directory are eligible. Active
processes, scheduled jobs and interrupted recovery protect their referenced files.
Unknown records and linked release boundaries remain untouched. Cleanup uses the
same application locks as deployment, skips busy apps, rechecks eligibility before
removal, and stops if its database lock is lost.

Live app directories, databases, uploads, backups and Manager update recovery files
are outside this cleanup. Deployment records and logs remain available. The page
reports logical file sizes; actual free space can differ because of shared files
and other disk activity. This cleanup covers applications on the Manager host.

## Update

From Manager 2.21.0 or newer, open **Settings → Manager updates**, download and
install 2.23.0. Offline installations can import the matching signed Node.js 22 or
24 update package. The updater briefly restarts Manager, keeps hosted applications
running and retains the previous version plus database/configuration backups.

## Validation

The local suite passed 432 tests with 12 optional integration tests skipped, plus
TypeScript and targeted lint checks. Retention tests cover Windows junctions,
recovery journals, runtime references, concurrent deployments, lost locks,
partial cleanup and scheduler exclusion. GitHub repeats the tests and production
build before publishing signed release packages.
