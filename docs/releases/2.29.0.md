# Manager 2.29.0

Administrators can remove pending, online, offline and revoked remote servers from the server directory or the server's Overview and Agent access pages.

Removal disconnects the agent and permanently deletes that server's Manager application records, saved environment values and service credentials, domain associations, job history, agent-update history and health history. A removal audit remains. Previously created backups may retain earlier records.

The physical server, installed agent, applications, databases, files, Caddy and other services, DNS records and provider billing are preserved. Removal does not uninstall or shut down the machine. Save the configuration and credentials you need before removal. Reconnection requires new enrollment and application import; it cannot restore the deleted management history.

Enrolled servers, including offline and revoked servers, require the exact server name and an explicit acknowledgement. Unused pending connections use a simpler confirmation. The review lists affected applications and queued operations. Both checks are enforced by the administrator-only API, which also rejects stale reviews and cross-origin requests. The Manager host cannot be removed through this feature.

Removal waits for active SSH setup, deployments, console work, domain changes, service installations and agent updates. Interrupted service installations and agent updates requiring recovery must be resolved first. Previously revoked work may still finish locally. Queued work is discarded without executing it. Database cleanup, credential invalidation and the retained audit are atomic and scoped to the selected server.

Validation covers isolated PostgreSQL removal with application and staging dependencies, authentication revocation, recovery and concurrency guards, stale confirmations, audit rollback and other-server isolation, plus API role/origin/maintenance checks. The existing agent remains version 1.6.0; no agent update is required for this feature.
