# Manager 2.28.3

Connected servers now use the same Health & alerts, Domains & DNS, Processes,
Runtimes & tools, console and update-version components as the Manager host.
All remote operations target the selected server. This release includes the
bodyless process-button request fix verified on the live Windows agent.

## Connected server operations

- Agent 1.6.0 adds application readiness, uptime, restart counts and resource
  metrics. Health history retains seven days of samples; alerts require repeated
  failures and resolve after two healthy checks.
- Start, stop and restart control registered applications in the agent's private
  PM2 registry. The UI waits for the agent's acknowledgement before reporting
  success. Active proxy configuration can be viewed and validated.
- Shared Caddy retains existing routes and its source configuration. Reload
  updates Manager-owned routes; stopping and restarting a shared proxy remain
  disabled to preserve existing sites.
- Shared domain forms support Cloudflare or existing/manual DNS. Remote routes
  must be acknowledged before DNS creation. Unmanaged DNS records are preserved;
  managed record deletion checks ownership. Domain aliases survive deployments.
- Runtime and version buttons open service setup for the selected server, with
  existing-service inspection, custom paths, SSH identity verification and a
  reviewed plan. Runtime versions can be installed alongside existing defaults.
- The shared terminal supports history, copy, clear, cancellation and contained
  directory changes. Agent updates use the existing supervisor and rollback flow.

Update connected agents from **Infrastructure > Agent access & updates** after
updating Manager. Existing agents continue reporting inventory, but the new
process controls require agent 1.6.0. Agent updates do not replace Manager,
database engines or existing service configuration. Remote health covers managed
applications and server resources; host-only backup, security and AI integrations
are not inferred from remote telemetry.

## Installer and update packages

Windows update actions now wake the registered Task Scheduler worker instead
of launching it inside Manager’s process tree. This lets installation continue
when PM2 stops Manager for backup. The existing independent recovery and
rollback checks remain in force.


This release retains the Windows installer hardening from 2.27.2: service and
port conflict checks, existing database/site preservation, custom PostgreSQL
paths, protected credentials, readiness checks and administrator sign-in checks.
Release preflight now rejects missing versioned notes before packaging.

Download `manager-setup-2.28.3-*.exe` or `manager-windows-2.28.3-*.zip`, with their
matching `.sha256.json` manifests. The EXE embeds the source package and still
requires internet access for dependencies. Existing Managers can use the
attested Node.js 22/24 update packages from **Settings > Manager updates**.

Validation covers Windows/Linux agent and SSH tests, PostgreSQL-backed remote
operations, production builds, fresh database initialization and installer
packaging smoke checks. Live Windows verification exercised process controls,
readiness alert/recovery, manual domain routes, console commands and verified TLS
while preserving existing Caddy, MariaDB and PostgreSQL processes and sites.

A complete installation and reboot on a clean Windows VM remain unverified.
The setup executable is not Authenticode signed; update-package provenance is
verified separately. See the [installer guide](https://github.com/elimichaells/synergy-deployer/blob/v2.28.3/installer/ManagerSetup/README.md).
